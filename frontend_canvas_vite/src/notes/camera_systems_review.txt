CAMERA SYSTEMS REVIEW (Duel Tactics frontend_canvas_vite)
Reviewed: 2026-08-02

=====================================================================
1. OVERVIEW
=====================================================================
Two mutually exclusive camera modes share one state object (app.camera):
  A) INPUT CAMERA / ASSESS MODE  -> app.camera.state === true, fixed=true
     Player browses the battlefield with zoom (N/S) and pan (E/W/N/S).
     Entered via the main-menu camera toggle (menuToggleCamera) or key "6"
     (app.toggleCameraMode, with a 4-frame startCount delay). mode switches
     zoom/pan via attack/defend keys or the CameraControl UI; dodge toggles
     the customView. While engaged:
        - in-flight player + AI actions COMPLETE (progression keeps running)
        - NO new player input or AI action can START (starters are gated)
        - already-moving projectiles keep flying and resolving damage
        - a flashing "ASSESS MODE" overlay + label is shown
  B) AUTO CAMERA                  -> app.settingAutoCamera === true
     Scripted zoom/pan (preInstructions + instructions) that follows combat
     (attackFocus/defendFocus), bolts (followBolt), spawns (playerSpawnFocus)
     or resets (zoomReset). Runs only when camera.state !== true && !fixed.
     Engaging assess mode while auto-cam runs CANCELS the auto-cam
     (resetAutoCamera) and enters assess mode at the current view.
Projectiles are tracked OUTSIDE the camera gate (playerUpdate ->
projectileTracker), so they always continue moving regardless of camera mode.

4. GATING / ACTION INTERACTION  (changed 2026-08-02)
=====================================================================
playerUpdate.js outer gate (line 111) was:
  if (!deflected && !dead && app.camera.state !== true) { progression + input }
-> This froze in-flight actions and left AI ungated during camera mode.

Now the outer gate only checks deflected/dead; progression always runs.
Gated during camera/assess mode (app.camera.state === true) so NO new
player/AI action can START:
  - checkMoveCancel      (dash initiation + move cancel)
  - checkFeintsCancels   (attack/defend/push feints & key-release cancels)
  - checkMoveInput       (new moves)
  - checkNonMoveInput    (attack/defend/dodge/item starts)
  - app.aiEvaluate       (AI decision generation)
  - checkAttacking       (held-dodge -> blunt conversion)
  - checkFlanking        (dodge+direction -> flank START)
AI starts actions ONLY by setting keyPressed flags (aiAct.js) consumed by the
same gated input checks, so gating those two checks blocks new AI actions too.

5. RESET SEMANTICS
=====================================================================
setAutoCamera has reset logic for attackFocusBreak/defendFocusBreak/zoomreset
(clears preInstructions/instructions, settingAutoCamera=false).
findFocusCell sets autoCamPanWaitingForPath=false.
NEW shared helper resetAutoCamera() (utils/functions/camera/resetAutoCamera.js)
clears all auto-cam flags and queues the event-log entry
"Auto camera cancelled — assess mode engaged". Used by menuToggleCamera and
the checkCamera input-mode start branch when auto-cam is busy, engaging assess
mode at the CURRENT view (view-at-default requirement skipped for that path).
